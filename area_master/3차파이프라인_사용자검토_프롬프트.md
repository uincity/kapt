======================================================================
0. 프로젝트 목적
======================================================================

기존 1차/2차 파이프라인을 통해 부산 전체 560개 단지 중:

- 최종 Master 확정: 462개
- 순수 임대 제외: 49개
- Still Pending: 49개

까지 처리되었다.

현재 정합성:

560
=
462 Master
+
49 EXCLUDED_RENTAL_ONLY
+
49 STILL_PENDING

이번 Phase 3의 대상은 오직:

data/review/phase2_still_pending.csv

에 존재하는 49개 단지이다.

기존 462개 Master와
49개 EXCLUDED_RENTAL_ONLY는 기본적으로 건드리지 않는다.

1. Phase 3 대상 구성
======================================================================

현재 남은 49개는 다음 4가지 그룹으로 구성되어 있다.

A. KB 매칭 저신뢰 / 모호
   약 20개

B. K-apt ↔ KB 세대수 불일치
   약 5개

C. KB 단지 미발견
   약 14개

D. 분양/임대 혼합단지
   약 10개

실제 phase2_still_pending.csv를 읽어

보고된 숫자를 하드코딩하지 않는다.

2. 최우선 원칙
======================================================================

이번 Phase 3는 "PENDING 0개 만들기"가 목적이 아니다.

목적은:

확실한 단지
→ VERIFIED

sale_apartment 대상이 아닌 단지
→ EXCLUDED

사람의 판단으로 확정 가능한 단지
→ MANUAL_VERIFIED

공식자료로 확인 가능한 단지
→ VERIFIED_OFFICIAL

끝까지 객관적 근거가 부족한 단지
→ FINAL_PENDING

상태로 만드는 것이다.

추측으로 VERIFIED 처리하지 않는다.

12. Manual Review 안전장치
======================================================================

사람이 후보를 선택하면 바로 VERIFIED 하지 않는다.

선택된 KB complex의:

- 주소
- 총세대수
- 법정동

을 다시 한번 K-apt와 비교한다.

명백한 충돌이 있으면:

WARNING

을 표시하고 재확인을 요구한다.

확정 시:

match_confidence = manual_verified
match_method = phase3_manual_selection

으로 저장한다.

26. 건축HUB fallback
======================================================================

KB와 공식 집계자료로도 해결하지 못한
이 소수 단지만 건축HUB를 사용한다.

여기서는 수천 세대 개별 조회가 발생해도
대상이 최대 약 14개 수준이므로 허용한다.

다만 먼저:

단지/유형별 집계데이터

가 존재하는지 확인한다.

집계형 데이터가 있으면
개별 세대 조회보다 우선 사용한다.


======================================================================
27. 건축물대장 최종 fallback
======================================================================

전유부/호별 데이터를 집계한다.

동일 정확한 전용면적별로:

COUNT(residential unit)

를 수행한다.

아파트 주거용이 아닌:

상가
오피스텔
부대시설

등은 제외한다.
